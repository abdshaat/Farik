# Keeping a content calendar

A calendar shows what is planned, why, and whose turn it is. Keep it as one table in
`docs/marketing/`, in plain text, so the user can read and edit it.

## 1. One table, six columns

| Date | Channel | Topic | The piece | Who publishes | Status |
|---|---|---|---|---|---|

- **Date**: the day it should go out.
- **Channel**: where it goes: the mailing list, a social account, the shop window, the website.
- **Topic**: what it is about, in a few words.
- **The piece**: where the finished words are, as a path to a file.
- **Who publishes**: always the human. You write the piece; you never send it.
- **Status**: one of idea, drafted, ready for the human, published.

## 2. Tie every row to a goal

Write the goal the calendar serves at the top, such as "more bookings for the spring classes" or
"more people trying the new feature". Each row should help that goal. A row that serves no goal
comes out.

## 3. Leave gaps

Do not fill the calendar to look busy. Two good pieces a month the human can actually publish
beat a full table nobody keeps up with. Match the number of rows to how much the business can
publish, and ask if you do not know.

## 4. Keep it true

When the human tells you something went out, change its status. When a date passes with the
piece still unpublished, say so in your note instead of quietly moving it. Add the result of each
published piece when the numbers are known, so the next plan learns from it.
