  Stop: []
---

# Release notes

Write for the people who use the product, not for developers.

1. Start with what changed, in one sentence.
2. Then where to find it.
3. Then anything they need to do. Say "nothing" if there is nothing.

Keep it under 150 words. No jargon, no ticket numbers.

# Deploy checklist

Before you say a change is ready:

1. The checks pass on the branch, and you pasted their output.
2. The change has a way back: say how to undo it.
3. Anything a customer sees has a line in the release notes.
4. Nothing in the change holds a key or a password.

If one of these fails, say which, and stop. See references/rollback.md.
