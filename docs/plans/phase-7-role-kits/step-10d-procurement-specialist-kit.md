## Goal

The Procurement Specialist ships a kit for researching anything to buy, technical or not: a used car, a baby car mirror, stock to resell, or a software subscription. Twelve skills, loaded on demand, and five services, each optional and each read-only or limited by an allowance. Exchange rates (Farik's own server over Frankfurter, no account), so every comparison is in one currency; web search for finding sellers and manufacturers (Exa's official server, no account, its search only: a page is opened by Claude Code's own `WebFetch`, on an approved site); shopping prices across Google Shopping, Amazon, eBay and Walmart (SerpApi's official server, a key, each search counted against an allowance because it spends the user's searches); what the company already spends with a seller (Brex's official server, signed in, read-only); and AWS's list prices for a software team (AWS's official server, a key that may only read prices). The agent suggests orders and follows them up; it never places, pays for or confirms one (ADR 0039, amended). Product-safety recalls and eBay listings, through Farik's own servers, are step 10g. Out of scope: any connector that can buy, check out, sign or send (ADR 0039; sending to sellers is step 10f, Farik's own act after the founder's approval); Exa with a key or signed in; Amazon's own buyer API, which needs an Associates account with ten qualifying sales in thirty days; supplier directories (Alibaba, ThomasNet and the rest), which offer no buyer API and forbid scraping; any new screen.

Its own dependencies are on ranges, which an exact pin of the top package does not hold; accepted as step 07 accepted it for Context7's alternatives. Rejected: Vantage (`https://mcp.vantage.sh/mcp`), which reads spend already made, not list prices; Infracost, community only.
  - **Finding sellers and manufacturers: Exa, official, `http`, `https://mcp.exa.ai/mcp`, no key, search only.** It answers `initialize` and `tools/list` without a key (server 3.2.1): `web_search_exa` and `web_fetch_exa`. Its documentation promises "free rate-limited usage" without a key, no number. `web_fetch_exa` is `denied`: its field is `urls`, so the hook checks the address, but Exa fetches on its own servers and follows a redirect to another site (checked 2026-10-07: `https://httpbin.org/redirect-to?url=https://example.com/` came back as example.com's page, labelled with the httpbin address), which the approved-sites check cannot see (spec 8.6 says the check relies on Claude Code's own fetch, which does not follow such a redirect), so any open redirect on an approved shop would reach any site; `WebFetch` already reads approved pages. `web_search_exa` stays `network` (the founder's answer): its results carry page text from any site, the agent sends those sites nothing, and its query and its required `objective` go to Exa as written. Exa now also takes a key in a header (`x-api-key` or `Authorization: Bearer`) and signs in by route 1 (`auth.exa.ai`, a registration endpoint, S256, `none`, scope `mcp:tools`); a key or a sign-in adds `agent_run` to its tools. The kit ships the keyless address, so its listing never shows `agent_run`; a key or a sign-in waits for a later plan that reads that tool, and a heavier user asks for more through a data pipeline (10e). Rejected: Tavily (`https://mcp.tavily.com/mcp/`, signs in by route 1 with registration; a candidate, the design keeps it), Brave Search and Perplexity (keys and a card), Firecrawl (a candidate for reading difficult pages).
  - **Shopping prices: SerpApi, official, `http`, `https://mcp.serpapi.com/mcp`, a pasted key.** Its server (2.0.0) lists `search`, `search_table` and `search_dashboard` without a key, and a call without one answers "Missing API key. Use path format /{API_KEY}/mcp or Authorization: Bearer"; the kit sends `headers: { Authorization: "Bearer {SERPAPI_KEY}" }`, `credential_keys: [SERPAPI_KEY]`, `key_page: https://serpapi.com/manage-api-key`. `search` takes any engine's parameters; the shops' engines are `google_shopping`, `amazon`, `ebay` and `walmart`. Its free plan gives 250 searches a month and at most 50 an hour (serpapi.com/pricing); each search spends one of the user's, so `search` is `external_effect` with an allowance, `calls: 50`, `what: "shopping searches"` (spec 6.7: a tool that spends the user's credits), and a search past it asks the founder before it reaches SerpApi. `search_table` and `search_dashboard` are `denied`: they are on-screen versions of `search` (for hosts that draw a service's own panels), take the same parameters and spend searches too, and the agent needs one way to search. Rejected: Amazon's Creators API (an Associates account with ten qualifying sales in thirty days), Keepa (paid, community server only).
  - **SerpApi's image addresses.** The engines `google_reverse_image` and `bing_reverse_image` take `image_url`, an address SerpApi fetches itself (the server's `serpapi://engines/<engine>` resources, 2026-10-07), and `google_lens` takes `url`. The hook at 7646c66 (`check_site_urls`, `governor/sites.rs:136`) checks only `url` and `urls`; step 10b2's landing-review fix judges every string that parses as an address, so `image_url` off the approved sites is refused `site_not_approved` before the connector is looked up (`judge_connector`, `daemon/hooks.rs:560`), and Task 3's guard holds it. An approved address is still fetched by SerpApi, whose redirect handling is unknown; spec 8.6 records it (Task 5).
  - **What the company already spends: Brex, official, `http`, `https://api.brex.com/mcp`, signed in (route 1).** Its resource (`https://api.brex.com`) names `https://api.brex.com` first as its authorization server, whose metadata has `registration_endpoint` `https://api.brex.com/v3/clients`, S256, `token_endpoint_auth_methods_supported` with `none`, and a revocation endpoint (read again 2026-10-07); `rmcp` uses the first. `oauth: { scopes: [offline_access, vendors.readonly, expenses.card.readonly, departments.readonly] }`, all four in its `scopes_supported`, so a write is not granted. Its bills scope, `expenses.bill`, also writes, so it is not asked, and `list_bills` and `get_bill_by_id` may fail under the four: the fallback below covers it. Before anyone signs in, an account admin or card admin accepts Brex's Developer API agreement under Settings, then Developer (developer.brex.com/docs/mcp, 2026-10-07). Its 43 tools are from that page, read 2026-10-05 and again 2026-10-07: the 11 and 32 below. Brex's server also accepts an API token as a bearer, which the live pin run uses. Rejected: Ramp's hosted server, whose tool list is generated at run time and includes card checkout (O4).
- **What each tag is.** One tool spends the user's credits, SerpApi's `search`, `external_effect` with its allowance; nothing else is `external_effect`. `fx`'s three tools and Exa's `web_search_exa` are `network`; `web_fetch_exa` is `denied` (above). AWS: the five price reads and `get_bedrock_patterns` are `network`; `analyze_cdk_project` and `analyze_terraform_project` are `denied` because they read the `project_path` the agent names on the user's computer, where a host server runs (spec 6.7), and `generate_cost_report` is `denied` because it writes its `output_file` there. Brex: 11 `network` (vendors, bills, merchants and categories, expense analytics, expenses, departments); 32 `denied`: every write, the people tools, the card, limit, bank and reward tools, travel, accounting and set-up, and the three Brex marks as writes though they look like reads. The people tools are `denied` although the Product Manager's kit keeps member lists `network` (step 06, P3): a buying decision needs a vendor, not a colleague's name, and Brex's user records carry card holders and limits. `list_expenses` and `get_expense_by_id` stay `network`: they hold a colleague's name on a card charge, which a recurring-charge search needs; `using-procurement-sources` says to report vendors and amounts, never people.
- **The `fx` server** is `farik_runtime::fx`, a hand-written `rmcp` `ServerHandler` over stdio, as `farik_runtime::osv` is (same features, no new crate), `serverInfo.name` `"farik-fx"`. Its address is the constant `FX_API = "https://api.frankfurter.dev/v2"`, never an argument, environment value or tool input; tests pass a fixture's address to the function, not the command. One `reqwest::Client` with `redirect::Policy::none()`, `no_proxy()`, no cookies, a 15-second timeout, reading at most 1 MiB in chunks; a larger answer is a tool error, "Frankfurter's answer is too large", sent nowhere. Inputs are checked before any request: a currency code `^[A-Z]{3}$`; `quotes` 1 to 30 distinct codes, none equal to `base`; a `date` an ISO date from `1999-01-04` to today in UTC. Tools, each answering plain JSON:
  - `latest_rates { base, quotes }` → `GET /rates?base=<base>&quotes=<a,b>` → `{ base, rates: { <quote>: { rate, date } } }`, each quote with the date Frankfurter gave for it, since its rows carry a date each and the central banks it reads publish on different days;
  - `rate_on { base, quote, date }` → `GET /rates?base=<base>&quotes=<quote>&date=<date>` → `{ date, base, quote, rate }`, `date` the one Frankfurter answered for, which may differ from the day asked, so the agent never claims a rate for a day that had none;
  - `list_currencies {}` → `GET /currencies` → `[{ code, name }]` from `iso_code` and `name` only, at most 400 entries.
  A non-2xx answer (a well-formed but unknown code is 422) is "Frankfurter could not answer that; check the codes and the date", without its body. The query is built with `Url::query_pairs_mut`, never by formatting strings. Verified against the live API on 2026-10-05: `date=2026-10-03` answered rows dated `2026-10-03`, and `quotes=EUR%2CGBP` (the encoded comma `query_pairs_mut` writes) was accepted.

## Tasks

### Task 1: The twelve skills

Files: `procurement_specialist/skills/{defining-the-need,finding-sellers-and-makers,comparing-offers,reading-terms-and-pricing,checking-a-seller,checking-product-safety,estimating-landed-cost,checking-a-used-vehicle,keeping-the-vendor-register,reviewing-renewals,writing-purchase-orders,using-procurement-sources}/SKILL.md`; `kit.yaml` `skills` in that order, and its header comment says what the kit holds; `embedded_skills`' arm. Step 10b's `its_kit_is_empty_until_step_10d` (`kit.rs:1072`) is deleted in this commit, since it asserts what this step changes. Each skill has `name` and the `description` given below, written in double quotes in the frontmatter since several hold a colon (the design's "Use when" column, made a sentence; changed only where ADR 0039's amendments require), numbered sections, under 6 KB, no `` !` `` and no attached file. Every one is written for any product, with an example of a physical good and of a service. Their descriptions and content:

- `defining-the-need` ("Use when a request names a thing to buy, before searching."): what it must do or be; the exact specification (model, size, standard it must meet, condition new or used); the quantity and how often; where and by when it must arrive; the budget; who uses it; one question per `farik_ask_human` call, at most four choices, only what changes the short list.
- `finding-sellers-and-makers` ("Use when building the seller list: maker first, then authorised sellers, then marketplaces, asking for any site not yet approved."): the maker first, then its authorised sellers, then marketplaces and resellers; for goods to resell, the maker or a wholesaler, never a retail listing; how to find a maker's contact page or a wholesale form; Exa's search and SerpApi's shops for finding them; a seller list of at least three where they exist; a maker's or seller's site not yet approved is asked for with `farik_request_sites`, all in one call; never a site's checkout, never a login, never a scraper of a site that forbids it.
- `comparing-offers` ("Use when there is more than one offer: unit price, breaks, shipping, warranty, returns, totals, one currency."): three to five offers; must-haves first, an offer failing one is out; unit price, quantity breaks, shipping, taxes and fees, warranty and returns; for a subscription the 12- and 36-month totals; with `fx` connected, every price converted with `rate_on` on the day it was read, the rate and date beside it (without it, `using-procurement-sources` says what to do); written with `farik_write_evaluation`, a table and then a recommendation in two sentences.
- `reading-terms-and-pricing` ("Use when about to recommend: what the price includes, minimums, delivery, warranty, renewals."): what the price includes; minimum order; delivery time; warranty, returns and refunds; auto-renewal and notice for a subscription; a DPA and where data is held for a service; an unclear term quoted for the founder, never interpreted; "not legal advice".
- `checking-a-seller` ("Use when about to trust a seller: age, address, reviews, scam signs; a software service's trust page."): how long it has traded, its address and company registration, its reviews across more than one site, marketplace seller ratings, signs of a scam (prices far below every other, payment only by transfer or gift card, no address, a new domain); for a software service its trust page (SOC 2 Type II, ISO 27001, two-factor, encryption); a review site or company register not yet approved is asked for with `farik_request_sites`, with the reason; what is missing, said plainly.
- `checking-product-safety` ("Use when the thing to buy is a physical product: recalls, the standard it must meet and the mark to look for."): recalls first, on the agency's own public page (the CPSC at `cpsc.gov` in the United States, the maker's own recall page), asked for with `farik_request_sites` since none is on Farik's list; the safety standard the product must meet where it is sold (for a child's car product, a car part or an electrical good, the standard by name and the mark to look for); never recommend a product with an open recall.
- `estimating-landed-cost` ("Use when goods ship: price, shipping, insurance, duty, tax and fees per unit delivered."): the price, shipping, insurance, import duty and tax, fees at the border, and the currency, as one number per unit delivered; say which figure is a guess and where to confirm it.
- `checking-a-used-vehicle` ("Use when the thing to buy is a used car: VIN, recalls, title, history report, inspection, comparable prices."): the VIN first, decoded on NHTSA's decoder (`vpic.nhtsa.dot.gov`) and its open recalls on NHTSA's recall lookup (`nhtsa.gov`), each asked for with `farik_request_sites`; the title's state, the history report the founder should buy, an inspection before money moves, comparable listings' prices for the same year, make, model and mileage; never say a car is sound.
- `keeping-the-vendor-register` ("Use when a task touches `vendors.xlsx`."): the sixteen columns in order, for sellers of goods as for subscriptions; ISO dates; values never formulas; read with `farik_read_sheet` before writing with `farik_write_sheet`; each order `farik_read_purchase_orders` gives as received written in with what was paid.
- `reviewing-renewals` ("Use when a renewal is to be reviewed."): usage against the plan, the price now and paid, alternatives' prices today; keep, change or cancel with the saving per year; what to ask the seller for; the decision date first.
