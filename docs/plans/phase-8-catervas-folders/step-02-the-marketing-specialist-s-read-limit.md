## Goal

The Marketing Specialist reads two folders of the project, the Product Manager's `docs/catervas/product/` and its own `docs/catervas/marketing/`, and nothing else of it, as the founder decided ("Read all; Marketing reads PM only"). Its sessions are registered with those read paths when they start, and the hook refuses its `Read`, `Grep`, `Glob` and `LS` outside them, a search that names no path, a command, and the diff of a task not its own, with `read_not_allowed`. Every other role reads as before. Its prompt and skills say where it reads what the product is and what shipped; `CHANGELOG.md`, which it could no longer read, becomes the Product Manager's, kept in a docs task it files at each sprint review. Out of scope: its writes (step 01's `folder_owned` and the contract's `allowed_paths` hold them); its connectors, `WebFetch` and `WebSearch`, which are not the repository; any other role's reading. No UI, no mockups, no event kind, no schema change, no migration.

## Decisions

- **Who is held: a role, fixed at session start, as `web` is (10b2).** In `catervas_core::folders`: `pub enum ReadAccess { Open, Only(Vec<String>) }` and `read_access(role)`, `Only` for `Role::MarketingSpecialist` with `[docs/catervas/product/**, docs/catervas/marketing/**]`, each `role_folder(..)` of the Product Manager and of the Marketing Specialist with `/**` after it, and `Open` for the eight others (the human included). `SessionRegistration` (`crates/runtime/src/daemon.rs:105`) gains `pub reads: ReadAccess` beside `web` (`:113`), set in `run_session` where `web` is (`crates/runtime/src/orchestrator/session.rs:161-178`, `:163`) from the agent's role, whatever the purpose: implement, verify, ceremony, conversation and chat alike, two Marketing Specialists alike. Rejected: reading the role from the team file at each call, as `judge` (`crates/runtime/src/daemon/hooks.rs:254`) could, which works while no agent changes role but fixes a session's limits a second way beside `web`; a tier of its own, which would change the tier table for one role.
- **When a glob stays within a read path: `stays_within(glob, read)`** in `crates/core/src/governor/paths.rs`, beside step 01's `reaches_the_folder`, pure, failing closed. `read` must be `<literal segments>/**` (no `*`, `?`, `[`, `{`, `.` or `..` segment before the `/**`), or nothing stays within it. `glob` stays within when it holds no `\` (a POSIX escape, which `normalise` would read as a separator) and every alternative of `expand_braces(glob)` (`paths.rs:186`) holds no `{` or `}` (a nested or unclosed group, which the engine may read otherwise), passes `normalise` (`:87`: not empty, not absolute, no `..`; `.` and empty segments dropped), and starts with the folder's segments, each equal to it exactly, letter case included. So `docs/catervas/product` and anything under it stay within, a wildcard before the folder's depth never does, and on a file system that ignores case `Docs/...` is refused, never wrongly allowed. Rejected: `!reaches_the_folder` (it asks the opposite question: `docs/*` reaches no folder and stays in none); comparing without case.
- **What the hook judges, and how a path is read.** For a session whose `reads` is `Only`, the built-ins that name a path, `Read` (`file_path`), `Grep`, `Glob` and `LS` (`path`), as `workspace_paths` (`hooks.rs:782`) reads them: from the session's working directory (its worktree, or the project's root for a conversation or a chat, either the repository's root, as every path check and the private-folder sessions judge them), links followed (`resolve`, `:839`: the hook does resolve links), so an absolute path inside the worktree and a path with `..` are judged as the repository path they reach, and a link out of a folder where it points. A `Glob` is judged as `<path>/<pattern>`, the path so resolved and the pattern as written; `workspace_paths` already refuses an absolute pattern, a `..` part and a `~` (`path_outside_workspace`). A `Grep`'s `glob` is not judged: it narrows what is under `path`. Any of the four naming no path, or the repository's root, is refused: it would read or search everything. `LS` is no longer in Claude Code (`BUILTIN_TOOLS`, `crates/runtime/src/claude.rs:35-56`) but has a tier (`builtin_tool_tier`, `hooks.rs:110`), so it is judged as `Grep`. `NotebookRead` is no built-in and is `tool_not_allowed` already. A read in the session's skills' folder (`in_skill_folder`, `:484`, which asks about no path) stays allowed. `.agent.md` twins are inside the folders, so they are read.
- **Catervas's tools.** `catervas_exec` is refused for a held session: a command reads the whole repository. The role holds no `execute` by default (`crates/core/src/governor/permissions.rs:55`), but the owner can grant it (10b2's landing review, finding 4). `catervas_git_diff` and `catervas_git_status` are refused when the session has a task whose assignee is not its agent, none included, and allowed on its own: the diff is the task branch's own work since it left the integration branch (`crates/store/src/git.rs:450`, three dots), ADR 0051's residual, but a contract may name a Marketing Specialist as reviewer (`reviewer_available`, `crates/core/src/governor/readiness.rs:357`, admits any role with an active agent). With no task, the tool's own `no_task` answers. Every other Catervas tool (contracts, board, rules, criteria, decisions, memory, notes, the marketing and post tools) reads Catervas's records, not the repository's files, and is not judged; nor are its connectors, `WebFetch`, `WebSearch` and `Skill`. Rejected: a sandbox mounting only the two folders (one role, one tier it does not hold by default); refusing the role as a reviewer at readiness (a rule for one role, for a rare contract).
- **Where and in which order.** `judge_call` asks a new private `judge_reads` last, after `evaluate_tool_call`, `plan_gate` (`:380`), the held `WebFetch` check (`:383`) and step 01b's `no_task_no_write`, so every reason given today stays the first. The hook alone holds it, as it alone holds the built-ins and a held session's sites; `Call::permit` is unchanged. A refusal is recorded as `tool.denied` with its reason by `record_decision` (`:864`) and does not stop the session. Reasons, exactly, `<folders>` being `ReadAccess::named`, `docs/catervas/product/ and docs/catervas/marketing/`:
  - a path: `read_not_allowed: <path> is outside what you may read (<folders>)`, `<path>` the repository path the hook resolved, or for a `Glob` that path, `/`, and the pattern;
  - no path: `read_not_allowed: <tool> names no path, or the whole repository; name a path inside what you may read (<folders>)`;
  - a command: `read_not_allowed: catervas_exec runs commands that can read the whole repository, outside what you may read (<folders>)`;
  - another's task: `read_not_allowed: <tool> shows a task that is not yours, outside what you may read (<folders>)`.
- **The session is told.** Step 01's `folders_line` ends, for a role whose `read_access` is `Only`, with `Read only <folders>: Catervas refuses a read anywhere else, and a search that names no path. Where a document there has an .agent.md twin beside it, read the twin, which is written for agents.` in place of `Read any of them, and …`; every other role's line is unchanged.
- **`CHANGELOG.md` becomes the Product Manager's** (the founder, 2026-10-10: "Marketing in its folder; PM owns CHANGELOG"). Claude Code's `Edit`, and its `Write` over a file that exists, need a `Read` of that file first, which the limit refuses, so the Marketing Specialist could not keep it. It writes customer-facing release notes and announcements in `docs/catervas/marketing/`, from the Product Manager's roadmap and sprint reports; its `role.yaml`, `system.md` and skills drop `CHANGELOG.md`. The Product Manager, which reads everything and since step 01b holds `write_workspace` and `git_local`, files, at each sprint review, a docs task of its own whose `allowed_paths` name `CHANGELOG.md`, and in it adds what the sprint's accepted tasks changed (a sprint review writes nothing itself: step 01b's `no_task_no_write`). Rejected: `CHANGELOG.md` among the Marketing Specialist's read paths, which "Marketing reads PM only" leaves out.
- **`CHANGELOG.md` gets no owner rule.** It is outside `docs/catervas/`, so `folder_owned` does not reach it, and the team's `document_paths` (`crates/core/src/governor/team_rules.rs:19`) already admit it for any documenting role's task; ownership lives in the two roles' prompts. Rejected: a readiness rule like `folder_owned` for one file outside the folders.
- **The Product Manager's `writing-task-contracts`** says that a Marketing Specialist's task names paths under `docs/catervas/marketing/` alone; step 01b's sentence on its own docs tasks admits `CHANGELOG.md` alone for its changelog task.
- **Its prompt and skills read the Product Manager's folder** for what the product is and what shipped (its `.agent.md` twins, its sprint reports), where they now say "a file in the project", "find it in the project" or "README" (exact texts in Task 4).
- **What stays outside the limit**, recorded in 5.6: the diff of its own task; the prompt's "The project" section, Catervas's scan of the stack (`.catervas/project.md`), which every agent is given; and a search through a link inside a readable folder, since a `Glob`'s pattern is not a path the hook resolves and Claude Code's search may follow the link: no tool the role holds makes a link, and step 03's write tool refuses one. A connector the owner adds to the role reads whatever its server reaches, and a public remote of the repository is readable through `WebFetch`; both stay outside the limit.
