# Phase 0, step 02: Schemas own their types

Status: draft
Branch: `phase/0-foundation`
Spec: `docs/SPEC.md` 5.3, 8.3; F4
Depends on: step 01 of this phase
Readiness confirmed by: its author, 2026-10-24, against the three rules of `docs/standards/workflow.md` stage 2 (Catervas ADR 0065)

Signatures, not bodies; test names and what each asserts, not test code; around 300 lines at most (Catervas ADR 0008).

## Goal

Every format Praeco writes or reads across a process boundary has one JSON Schema in `docs/schemas/`, and its TypeScript types and validator are generated from it. `pnpm generate` writes them under `packages/schemas/src/generated/`; `pnpm check` fails when a committed generated file is stale. `@praeco/schemas` turns a `snake_case` wire value into a validated `camelCase` domain value (`parse`) and back (`toWire`). The first schema is the job contract of SPEC 5.3.

Out of scope: what a valid contract means beyond its shape (budget within limits, tools within the program: phase 1 step 02), the event schemas (step 03).

## Decisions

- **Generated module per schema.** For `docs/schemas/<kebab>.schema.json`, `pnpm generate` writes `packages/schemas/src/generated/<kebab>.ts` holding, in this order: a banner `// Generated by scripts/generate.ts from docs/schemas/<kebab>.schema.json. Do not edit.`; the wire type from `json-schema-to-typescript` 16.0.0, named `<Pascal>Wire` (the generator passes that name and drops the schema's `title` for the call, so the schema keeps a human title); and `export const <camel>Schema = <the schema as JSON> as const;`. The file is formatted by Biome's formatter before it is written, so `biome check` accepts it, and Biome's linter skips `**/generated` (as Catervas's `biome.json` does).
- **No `$defs`, no data as keys.** Schemas inline nested objects, so every generated type is one declaration; and no schema uses an object whose keys are data (a map from tool name to count is an array of `{ tool, count }`), because `toCamel` maps every key.
- **Validation at run time** with Ajv 8.20.0 (`ajv/dist/2020`), `allErrors: false`, `strict: true`, and `ajv-formats` 3.0.1 for `uuid`, `date-time` and `uri`. One Ajv instance in `packages/schemas/src/registry.ts` compiles each schema on first use and keeps it. Rejected: Ajv's standalone code generation, which commits generated JavaScript into a workspace that has none.
- **`parse(name, value)`** validates the wire value, then maps its keys with `toCamel` and returns it typed as `Domain[N]`. **`toWire(name, value)`** maps keys with `toSnake` and does not validate (the value is already typed; validating twice at every write is waste).
- **`Domain[N]`** is `CamelKeys<Wire[N]>`, a recursive type that renames `snake_case` keys to `camelCase` through objects and arrays and leaves values alone.
- **`toCamel` and `toSnake`** walk plain objects and arrays; `Date`, strings, numbers, booleans and `null` pass through; a key's first letter is never changed and only `_x` becomes `X` (and back).
- **`SchemaName`** is the file's kebab name in `snake_case`: `job-contract.schema.json` is `'job_contract'`. `scripts/generate.ts` also writes `packages/schemas/src/generated/index.ts`, which exports every generated module and the `Wire` map type `{ job_contract: JobContractWire }` and the `SCHEMAS` table `{ job_contract: jobContractSchema }`.
- **The job contract's shape** (SPEC 5.3; `$schema` 2020-12, `$id` `https://praeco.dev/schemas/job-contract.schema.json`, `title` "Job contract", `additionalProperties: false`, every property required):
  - `job_id`, `workspace_id`: `string`, `format: uuid`.
  - `program`: `enum ["research", "request"]`; later phases add values.
  - `intent`: `string`, 20 to 600 characters.
  - `expects`: array of 1 to 5 `{ kind: enum ["finding"], at_least: integer 1 to 100 }`.
  - `allowed_tools`: array of 1 to 30 unique strings, `pattern: ^[a-z][a-z_]*$`.
  - `budget`: `{ usd_micros: integer, minimum 10000, multipleOf 10000 (whole cents, as the session budget takes them, ADR 0013); minutes: integer 1 to 60; tool_calls: integer 1 to 500 }`.
  - `requested_by`: `string` `format: uuid`, or `null`.
  - `created_at`: `string`, `format: date-time`.
- **`scripts/generate.ts --check`** renders every module in memory and compares it with the file on disk; it prints `stale: <path>` per difference (including a generated file with no schema) and exits 1. `scripts/check.ts` runs it first, as stage `generate`.
- **`@praeco/schemas` has no I/O** besides Ajv's compile; `scripts/core-io.ts` already lets `@praeco/core` import it.

## Interfaces

Consumes: `Result`, `ok`, `err` (`@praeco/core`, step 01).

Produces:

```ts
// @praeco/schemas
export type CamelKeys<T> = /* recursive key renaming */;
export function toCamel(value: unknown): unknown;
export function toSnake(value: unknown): unknown;
export type SchemaName = keyof Wire;                  // 'job_contract'
export type Domain = { [N in SchemaName]: CamelKeys<Wire[N]> };
export interface SchemaError { kind: 'invalid'; schema: string; path: string; message: string }
export function parse<N extends SchemaName>(name: N, value: unknown): Result<Domain[N], SchemaError>;
export function toWire<N extends SchemaName>(name: N, value: Domain[N]): Wire[N];
export type { JobContractWire } from './generated/index.ts';
export type JobContractDomain = Domain['job_contract'];
// @praeco/schemas/fixtures
export function aJobContractWire(overrides?: Partial<JobContractWire>): JobContractWire;  // a valid research contract

// scripts/generate.ts
export interface GeneratedFile { path: string; text: string }
export function renderAll(schemaDir: string): Promise<GeneratedFile[]>;
export function findStale(rendered: readonly GeneratedFile[], onDisk: readonly GeneratedFile[]): string[];
```

## Tasks

### Task 1: The generator and the key mapping

Files: created `scripts/generate.ts`, `scripts/generate.test.ts`, `packages/schemas/package.json`, `packages/schemas/tsconfig.json`, `packages/schemas/src/case.ts`, `packages/schemas/src/case.test.ts`, `packages/schemas/src/index.ts`, `packages/schemas/src/generated/index.ts` (empty maps); modified `scripts/check.ts`, `package.json` (`"generate": "node scripts/generate.ts"`, dev dependencies `json-schema-to-typescript` 16.0.0; `packages/schemas` depends on `ajv` 8.20.0 and `ajv-formats` 3.0.1).
Produces: `renderAll`, `findStale`, `toCamel`, `toSnake`, `CamelKeys`.

Tests:

- `renderAll` and `findStale` — asserts that rendering a temporary folder holding one schema `{ "title": "Thing", "type": "object", "properties": { "some_field": { "type": "string" } }, "required": ["some_field"], "additionalProperties": false }` named `thing.schema.json` yields `generated/thing.ts` declaring `export interface ThingWire` with `some_field: string` and `export const thingSchema`, and `generated/index.ts` mapping `thing` to both; and that `findStale` names the file when the schema's text changes and names an extra generated file with no schema.
- `toCamel` and `toSnake` — asserts that `{ allowed_tools: ['record_finding'], budget: { usd_micros: 1 }, created_at: '2026-10-24T00:00:00Z', items: [{ at_least: 1 }] }` becomes `{ allowedTools: ['record_finding'], budget: { usdMicros: 1 }, createdAt: '2026-10-24T00:00:00Z', items: [{ atLeast: 1 }] }` and back, with array values and string values untouched.

- [ ] `feat(schemas): generate types from json schemas and map key case`

### Task 2: The job contract's schema

Files: created `docs/schemas/job-contract.schema.json`; generated `packages/schemas/src/generated/job-contract.ts` and regenerated `index.ts` by running `pnpm generate`.

No test of its own: the schema is data; Task 3's parse test exercises it, and `pnpm check`'s generate stage keeps it in step with its module.

- [ ] `feat(schemas): add the job contract schema`

### Task 3: Parsing

Files: created `packages/schemas/src/registry.ts`, `parse.ts`, `parse.test.ts`, `src/fixtures/index.ts`, `src/fixtures/job-contract.ts`; modified `src/index.ts`, `package.json` (`exports` adds `./fixtures`).
Consumes: `toCamel`, `toSnake` (Task 1), the generated job contract (Task 2).
Produces: `parse`, `toWire`, `SchemaError`, `Domain`, `aJobContractWire`.

Tests:

- `parse` — asserts that `aJobContractWire()` parses to a value whose `allowedTools`, `budget.usdMicros` and `expects[0].atLeast` equal the wire's, that `toWire('job_contract', that value)` deep-equals the wire, and that a contract with `budget.usd_micros: 12345` is refused with `kind: 'invalid'`, `schema: 'job_contract'` and `path: '/budget/usd_micros'`.

- [ ] `feat(schemas): parse wire values into camel-case domain values`
